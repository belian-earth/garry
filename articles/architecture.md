# Architecture: an interactive map of garry

garry is a lazy raster engine: verbs build an R-native compute graph, a
planner fuses it into schedulable stages, and executors run those stages
as XLA kernels (anvl traces each to a StableHLO program, pjrt compiles
it) over GDAL-read chunks (via gdalraster). This article maps that
structure interactively at two zoom levels. Both graphs are generated by
static analysis of the package sources (`package-graph/build_graph.R` in
the repository); nothing here is hand-drawn. The pages embed a snapshot,
so rerun the script below after changing `R/`.

## The exported API surface

Every node below is an exported function, colour-coded by subsystem. An
edge `A -> B` means calling `A` reaches `B`, possibly through internal
code; edges to the gold triangle (anvl, the XLA compiler frontend) and
the green square (gdalraster, GDAL IO) show which verbs ultimately touch
which backend. Grey diamonds are other packages, among them pjrt and
stablehlo, the compile path for the kernels anvl traces. Click a node to
highlight its one-hop neighbourhood, use the dropdowns to jump to a
function or filter a subsystem, and scroll to zoom.

Two things are worth reading directly off this graph. First, the
lazy-verb layer
([`lazy_map()`](https://belian-earth.github.io/garry/reference/lazy_map.md),
[`focal_map()`](https://belian-earth.github.io/garry/reference/focal_map.md),
[`reduce_over()`](https://belian-earth.github.io/garry/reference/reduce_over.md),
and friends) reads no data and compiles nothing. While building, it
reaches anvl only to read a kernel’s output dtype: an abstract trace
when
[`lazy_map()`](https://belian-earth.github.io/garry/reference/lazy_map.md)
or
[`scan_over()`](https://belian-earth.github.io/garry/reference/scan_over.md)
has no `dtype`, or
[`reduce_over()`](https://belian-earth.github.io/garry/reference/reduce_over.md)
has a custom reducer. Its pjrt edges come from fingerprinting arrays a
kernel body captures, which keys that dtype trace so a kernel repeated
across bands or slices traces once; nothing is compiled. Its other anvl
edges, such as
[`apply_mask()`](https://belian-earth.github.io/garry/reference/apply_mask.md)’s,
are the bodies of the kernels it builds, which run at execution. Its one
GDAL edge is `shrink_footprint(boundary = "keep")`, which writes a
sourceless VRT marking the grid’s interior. Second, pixels are read and
kernels run only by the execution verbs
([`collect()`](https://belian-earth.github.io/garry/reference/collect.md),
[`materialise()`](https://belian-earth.github.io/garry/reference/materialise.md),
[`preview()`](https://belian-earth.github.io/garry/reference/preview.md),
[`write_tif()`](https://belian-earth.github.io/garry/reference/write_tif.md),
[`extract_points()`](https://belian-earth.github.io/garry/reference/extract_points.md),
[`lazy_value_and_grad()`](https://belian-earth.github.io/garry/reference/lazy_value_and_grad.md),
and the executors beneath them), which is the lazy contract made
visible;
[`plan_lazy()`](https://belian-earth.github.io/garry/reference/plan_lazy.md)
reaches both backends to prepare warped reads and kernels without
running them. The other GDAL edges read file headers and CRS definitions
([`lazy_source()`](https://belian-earth.github.io/garry/reference/lazy_source.md),
[`lazy_dataset()`](https://belian-earth.github.io/garry/reference/lazy_dataset.md),
[`grid_from_src()`](https://belian-earth.github.io/garry/reference/grid_from_src.md),
[`grid_from_bbox()`](https://belian-earth.github.io/garry/reference/grid_from_bbox.md)),
build tile indexes and staged cubes, or set GDAL configuration. The
other anvl edges belong to the `g_*` vocabulary and the kernel bodies
written in it
([`geomedian()`](https://belian-earth.github.io/garry/reference/geomedian.md),
[`kalman_llt()`](https://belian-earth.github.io/garry/reference/kalman_llt.md),
[`band_project()`](https://belian-earth.github.io/garry/reference/band_project.md)
and the like).

## The full internal call graph

The map below is the same analysis over every top-level definition in
the package: functions, S7 classes (boxes), generics (ellipses) and
methods (hexagons), with dashed edges for S7 dispatch. It exists for
contributors; users never need it, but it answers structural questions
quickly. Where does the anvl boundary sit? Every gold edge originates in
`ops.R` (the `g_*` vocabulary), as do the edges to pjrt and stablehlo; a
test enforces the rule for anvl and pjrt. Which subsystems are large?
Node size tracks line count, so the scheduler and the GDAL adapter stand
out immediately.

## Subsystems

The colour groups in both graphs correspond to the package’s subsystems:

- **IR & graph**: the node types, the `g_*` op vocabulary, the graph
  container, and the planner passes that fuse nodes into stages.
- **Grid & geometry**: `GridSpec`, chunk grids, and grid construction
  helpers. Every lazy object is pinned to a grid; planning is
  grid-identity-trivial by design.
- **Execution**:
  [`collect()`](https://belian-earth.github.io/garry/reference/collect.md)
  down through the scheduler, daemon pool, the kernel programs sent to
  daemons, and the direct composite executors.
- **IO & GDAL**: the gdalraster adapter, dataset/STAC construction, HTTP
  authentication, and materialisation.
- **Models & kernels**: OmniCloudMask, the Kalman and Hampel smoothers,
  band projection, and dequantisers.
- **Viz & UX**:
  [`plan_draw()`](https://belian-earth.github.io/garry/reference/plan_draw.md),
  [`plan_view()`](https://belian-earth.github.io/garry/reference/plan_view.md),
  [`preview()`](https://belian-earth.github.io/garry/reference/preview.md),
  and task reports.
- **Infra**: options and package start-up.

## Regenerating

Both graphs, plus a report of the exact anvl functions garry calls, are
rebuilt from source with:

``` r

# from the package root
source("package-graph/build_graph.R")
```

The script parses `R/*.R` without evaluating it, so it runs on any
machine with `visNetwork`, `igraph` and `glue` installed.
